# Сборки распознавателя речи для acroama

Этот репозиторий каждый день сам проверяет, вышла ли новая версия whisper.cpp. Если вышла, он собирает из неё программу `whisper-cli` для Mac на Apple Silicon (macOS 11.0 и новее), публикует её и обновляет список версий `manifest.json`. Приложение acroama читает этот список и из своего окна устанавливает и обновляет распознаватель речи.

Всё работает на машинах GitHub. На вашем Mac ничего запускать не нужно.

## Как завести репозиторий (один раз)

1. Создайте на GitHub новый репозиторий, например `acroama-modules`. Сделайте его **публичным** (Public): тогда приложение скачивает файлы без входа в аккаунт.
2. Скопируйте в него всё содержимое этой папки, включая скрытую папку `.github`: `.github/workflows/whisper-cpp.yml`, `scripts/`, `manifest.json` и этот `README.md`. Папку `tests/` копировать не нужно. Отправьте файлы в ветку по умолчанию (`main`).
3. Откройте в репозитории **Settings → Actions → General**:
   - в разделе «Actions permissions» выберите «Allow all actions and reusable workflows»;
   - в разделе «Workflow permissions» выберите **«Read and write permissions»** и нажмите «Save». Без этого первый запуск не сможет опубликовать сборку.
4. Откройте вкладку **Actions**, выберите слева сценарий **whisper-cpp** и нажмите **Run workflow** (это ручной запуск). Дождитесь конца запуска.
5. Когда запуск закончится зелёной галочкой, откройте **Releases** (справа на главной странице репозитория). Там должны появиться два выпуска:
   - `whisper-cpp-<версия>` с файлом `whisper-cli`;
   - `manifest` с файлом `manifest.json`.
6. Пришлите разработчику приложения адрес репозитория: имя аккаунта и имя репозитория, например `<аккаунт>/acroama-modules`. Он впишет в приложение адрес списка версий:

   ```
   https://github.com/<аккаунт>/<репозиторий>/releases/download/manifest/manifest.json
   ```

Больше ничего делать не нужно.

## Что происходит каждый день

Сценарий запускается сам в 03:17 по UTC:

1. Узнаёт номер последнего выпуска whisper.cpp.
2. Сравнивает его с версией в `manifest.json`. Если они совпадают, сразу переходит к шагу 5.
3. Если версия новая, собирает `whisper-cli` (`scripts/build-whisper-cli.sh`).
4. Публикует выпуск `whisper-cpp-<версия>` с этой программой и вписывает её в `manifest.json`: версию, адрес, размер и отпечаток (SHA-256), по которому приложение проверяет скачанный файл.
5. Записывает в `manifest.json` время проверки (`checkedAt`), делает коммит `manifest: checked <дата>` и заменяет файл `manifest.json` в выпуске `manifest`.

**Зачем ежедневный коммит.** GitHub отключает расписание в репозитории, где 60 дней не было никаких изменений. Ежедневный коммит — это и есть такое изменение, поэтому расписание работает без вас.

**Если пришло письмо о неудачном запуске.** Значит, сборка или сеть подвели в этот день. Ничего не опубликовано, `manifest.json` остался прежним, приложение по-прежнему предлагает предыдущую версию. Обычно следующий день проходит сам. Если запуски падают много дней подряд, время проверки в списке стареет, и через 90 дней приложение покажет предупреждение, что список версий давно не обновлялся. Тогда откройте неудачный запуск на вкладке Actions и перешлите ссылку на него разработчику.

## Файлы

| Файл | Что это |
|---|---|
| `.github/workflows/whisper-cpp.yml` | ежедневный сценарий сборки |
| `scripts/build-whisper-cli.sh` | собирает `whisper-cli` для одной версии whisper.cpp; с `--dry-run` только печатает команды |
| `scripts/update_manifest.py` | записывает `manifest.json` |
| `manifest.json` | список версий, который читает приложение |
